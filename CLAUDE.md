# CLAUDE.md — Caido Wordsmith Plugin

This file documents the codebase structure, development workflows, and conventions for AI assistants working on this project.

---

## Project Overview

**Caido Wordsmith** is a [Caido](https://caido.io) plugin that generates security testing wordlists (similar to Burp Intruder's payload generators) within Caido's plugin model. The plugin focuses on **payload generation and export** — not reimplementing a request engine — since Caido Automate already handles running payloads from hosted files.

### Key Design Principles

- Generate payloads in the backend; the frontend is UI-only.
- Stream output line-by-line; never hold giant wordlists in memory.
- Treat Caido Automate as the primary downstream consumer.
- Do not recreate Burp Intruder's full attack engine in v1.
- Prefer preview + save/export over immediate request execution.
- Validate and reject combinations that would explode combinatorially.

```
    │       ├── page.ts         ← renders the main UI page
    │       ├── api.ts          ← typed wrappers around backend RPC calls
    │       └── components/     ← reusable UI components (Vue/vanilla)
    └── backend/
        └── src/
            ├── index.ts        ← backend entry point; wires RPC + events
            ├── rpc.ts          ← exposes previewWordlist / generateWordlist
            ├── events.ts       ← progress event emitters to frontend
            ├── output.ts       ← file writing / streaming logic
            └── generator/
                ├── common.ts   ← shared types, deduplication, helpers
                ├── charset.ts  ← brute-force charset generator
                ├── mask.ts     ← mask-based generator (?l ?u ?d ?s tokens)
                └── mangle.ts   ← word mangling / mutation generator
```

## Shared Data Model

The central type shared between frontend and backend:

```ts
type GenerateOptions = {
  mode: "charset" | "mask" | "mangle";
  charset?: string;
  minLength?: number;
  maxLength?: number;
  mask?: string;
  words?: string[];
  prefixes?: string[];
  suffixes?: string[];
  years?: string[];
  separators?: string[];
  capitalize?: boolean;
  uppercase?: boolean;
  lowercase?: boolean;
  leetspeak?: boolean;
  dedupe?: boolean;
  previewLimit?: number;
};
```

Define this in `packages/backend/src/generator/common.ts` and import it in the frontend via the shared types path.

## Development Workflow

### Prerequisites

- Node.js (LTS)
- pnpm (preferred) or npm
- Caido running locally for live plugin testing

### Setup

```bash
pnpm install
pnpm dev        # start frontend + backend in watch mode
```

### Build

```bash
pnpm build      # production build
```

### Key Config Files

**`manifest.json`** — declares plugin ID, name, version, and entry points for frontend and backend.

**`caido.config.ts`** — Vite-based build config generated by Caido tooling. Do not restructure this file without consulting the [Caido config guide](https://developer.caido.io/guides/config.html).

## Frontend Conventions

- The frontend registers a single navigation page called `Wordlist Generator`.
- Use the [Caido component library](https://developer.caido.io/guides/styling.html) for all UI elements to stay consistent with the Caido shell.
- All backend calls go through `packages/frontend/src/api.ts` — never call RPC directly from `page.ts` or components.
- Keep the preview panel limited to the first N results (configurable, default 100) — never stream the full wordlist to the frontend.
- Show combinatorial-explosion warnings inline before the user triggers generation.

### UI Sections (page.ts)

1. **Mode selector** — charset / mask / mangle
2. **Options form** — fields change depending on selected mode
3. **Preview panel** — shows first N outputs after `Preview` RPC call
4. **Action bar** — `Preview`, `Generate`, `Save wordlist` buttons
5. **Progress indicator** — shown during generation (driven by backend events)
6. **Help text** — explains how to load the output into Caido Automate

---

## Backend Conventions

- All generation logic lives under `packages/backend/src/generator/`.
- Each generator module exports a single generator function that **yields** strings (generator function / async iterator) — do not return arrays.
- `output.ts` is the only place that writes to disk; generators never write files directly.
- `rpc.ts` validates input before calling any generator; reject early if limits are exceeded.
- `events.ts` emits progress events during long-running generation jobs.

### RPC Functions

| Function | Description |
|---|---|
| `previewWordlist(options)` | Returns first N entries without writing a file |
| `generateWordlist(options)` | Runs full generation, writes `.txt` file, returns metadata |

Both functions return:
```ts
{
  totalGenerated: number;
  previewCount: number;      // how many entries in the preview array
  outputFilename?: string;   // only on generateWordlist
  durationMs: number;
}
```

### Generator Modules

| File | Responsibility |
|---|---|
| `generator/common.ts` | `GenerateOptions` type, deduplication set, shared helpers |
| `generator/charset.ts` | Brute-force combinations over a charset with min/max length |
| `generator/mask.ts` | Parse and expand masks using `?l` `?u` `?d` `?s` tokens |
| `generator/mangle.ts` | Produce word mutations: capitalize, leet, prefix/suffix/year combos |

Each generator must be independently testable with no side effects.

## Generation Modes

### Charset / Brute-force

Iterates all combinations of a given character set between `minLength` and `maxLength`. Guard against combinations that exceed a configurable hard limit (e.g., 10M entries) and return an error before starting.

### Mask

Parses a mask string where:
- `?l` = lowercase letters
- `?u` = uppercase letters
- `?d` = digits
- `?s` = special characters
- Any other character = literal

Reject malformed masks before starting generation.

### Word Mangler

Given a list of base words, produces mutations:
- Original word
- Capitalized (`Word`)
- Uppercase (`WORD`) / lowercase (`word`)
- `prefix + word`, `word + suffix`
- `word + year` (e.g., `word2024`)
- `word + separator + word`
- Leetspeak substitutions (`a→4`, `e→3`, `i→1`, `o→0`, `s→5`)

Apply deduplication via a `Set` across all mutations.

---

## File Output

- Output files are saved as `.txt`, one entry per line.
- File writing is handled exclusively in `output.ts` using streaming writes (do not buffer the full list).
- Output must be accessible to the user so they can load it into Caido Automate as a **Hosted File** or paste it as a **Simple List**.
- Refer to [Caido Automate wordlists](https://docs.caido.io/app/guides/automate_wordlists) for how the end-user consumes the file.

---

## Events / Progress

- During generation, the backend emits `wordlist:progress` events carrying `{ processed: number, total: number }`.
- The frontend listens for these events and updates a progress bar.
- Emit events at most every 1000 entries to avoid flooding the IPC channel.
- Implement cancel support via a flag checked inside the generator loop.

---

## Settings Persistence

Use the Caido frontend storage API ([guide](https://developer.caido.io/guides/frontend_storage.md)) to persist:
- Last-used options per mode
- Named presets (username mutations, password season/year, numeric pins)
- Recent generation history (filename + metadata only, not the full wordlist)

## Build Order (MVP)

1. Scaffold plugin (`manifest.json`, `caido.config.ts`, package structure)
2. Add UI page with form (mode selector + options)
3. Implement `previewWordlist` RPC + mangle generator
4. Wire frontend `api.ts` to call preview and display results
5. Implement `generateWordlist` RPC + file output streaming
6. Add charset generator
7. Add mask generator
8. Add progress events + cancel support
9. Persist settings / presets
10. Test with Caido Automate end-to-end
11. Polish README, icon, and packaging

## Testing Checklist

- [ ] Small generation jobs (< 1000 entries)
- [ ] Medium jobs (10k–100k entries)
- [ ] Large jobs (> 1M entries) — verify streaming, no OOM
- [ ] Duplicate handling and deduplication correctness
- [ ] Mask parsing edge cases (empty mask, unknown tokens, only literals)
- [ ] Invalid / malformed input rejection in RPC
- [ ] Plugin behavior when generation is cancelled mid-run
- [ ] Output `.txt` file loads correctly in Caido Automate as Hosted File

## Out of Scope (v1)

- Recreating Burp Intruder's full attack engine
- Crawl-derived candidate words
- Response-aware iteration
- Multi-payload strategies
- Headless pipeline batch jobs
